# Media Client

Python-клиент для digital signage: приложение регистрируется на сервере, получает актуальный список медиафайлов, скачивает их локально и воспроизводит в полноэкранном режиме через `mpv`.

Клиент рассчитан в первую очередь на Linux-устройство с графической сессией и автозапуском через `systemd`.

## Что умеет

- отправляет `heartbeat` на сервер и отслеживает статус устройства;
- синхронизирует токен устройства;
- проверяет, нужно ли обновить контент;
- скачивает видео, изображения и PDF;
- конвертирует PDF в PNG-страницы через `pdftoppm`;
- воспроизводит локальный контент по кругу через `mpv`;
- поддерживает длительности показа для изображений и страниц PDF;
- умеет работать по расписанию показа;
- может переводить устройство в `freeze`/`suspend` до следующего окна вещания через `rtcwake`.

## Структура репозитория

- [client.py] — основной клиент.
- [config.json] — локальная конфигурация устройства.
- [requirements.txt] — Python-зависимости.
- [mediaDist.service] — пример `systemd` unit-файла.
- `content/` — директория с загруженным контентом.

## Требования

### Python

- Python 3.10+;
- `pip`;
- зависимости из [requirements.txt].

### Системные зависимости

Для полноценной работы клиенту нужны внешние утилиты:

- `mpv` — воспроизведение контента;
- `wget` — скачивание файлов с сервера;
- `pdftoppm` из пакета `poppler-utils` — конвертация PDF в PNG;
- `rtcwake` — перевод устройства в сон по расписанию;
- графическая среда/X11 для окна `tkinter`.

Пример установки для Debian/Ubuntu:

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip mpv wget poppler-utils util-linux python3-tk
```

## Быстрый старт

### 1. Создать виртуальное окружение

```bash
python3 -m venv my_venv
source my_venv/bin/activate
pip install -r requirements.txt
```

### 2. Настроить `config.json`

Основные параметры:

- `server_url` — адрес backend-сервера;
- `device_id` — идентификатор устройства;
- `token` — токен устройства;
- `media_dir` — абсолютный или относительный путь к локальному каталогу контента;
- `heartbeat_interval` — интервал heartbeat в секундах;
- `check_videos_interval` — интервал проверки обновлений контента в секундах;
- `image_display_duration` — длительность показа изображений по умолчанию;
- `schedule` — расписание вещания в формате:

```json
{
  "start_time": "09:00",
  "end_time": "18:00"
}
```

- `schedule_suspend_enabled` — включить перевод устройства в сон вне окна вещания;
- `schedule_suspend_mode` — режим для `rtcwake`, по умолчанию `freeze`;
- `schedule_wakeup_margin_minutes` — за сколько минут до начала вещания просыпаться;
- `schedule_poweroff_enabled` — флаг для совместимости конфигурации; при `true` также включает `schedule_suspend_enabled`.

Если `schedule` равен `null`, клиент работает без ограничений по времени.

## Запуск

```bash
source my_venv/bin/activate
python client.py
```

При старте клиент:

1. загружает и валидирует конфиг;
2. применяет расписание;
3. сразу делает первую проверку контента;
4. запускает фоновые циклы `heartbeat` и `check-videos`;
5. показывает или скрывает черный fullscreen-экран в зависимости от статуса и расписания.

## Как хранится контент

После обновления клиент полностью очищает каталог `media_dir` и скачивает новую версию контента заново.

Дополнительно рядом с файлами создается служебный файл:

- `.durations.json` — длительности показа для изображений, видео и страниц PDF.

Имена локальных файлов строятся из `id`, который приходит от сервера.

## Взаимодействие с сервером

Клиент использует следующие API-эндпоинты:

- `POST /api/heartbeat`
- `POST /api/check-videos`
- `POST /api/sync-token`

Ожидаемое поведение:

- при `heartbeat` сервер подтверждает, что устройство активно, заблокировано или требует обновления токена;
- при `check-videos` сервер сообщает, нужно ли обновлять контент;
- если сервер возвращает расписание, клиент сохраняет его в локальный [config.json].

## Автозапуск через systemd

В репозитории есть шаблон [mediaDist.service].

Перед использованием замените в нем:

- `<user>` на реального пользователя;
- пути `/home/<user>/media-client/...` на актуальный путь к репозиторию;
- при необходимости `DISPLAY` и `XAUTHORITY` под вашу графическую сессию.

Пример установки:

```bash
sudo cp mediaDist.service /etc/systemd/system/mediaDist.service
sudo systemctl daemon-reload
sudo systemctl enable mediaDist.service
sudo systemctl start mediaDist.service
```

Проверка статуса:

```bash
systemctl status mediaDist.service
journalctl -u mediaDist.service -f
```

## Советы по эксплуатации

- Клиент нужно запускать на Linux, потому что `rtcwake` и типичный `systemd`-сценарий ориентированы именно на него.
- Для локальной разработки на macOS или Windows часть функций может не работать или работать частично.
- При обновлении контента каталог `media_dir` очищается полностью, это нормальное поведение клиента.

## Отладка

Если клиент не воспроизводит контент, стоит проверить:

1. доступность `server_url`;
2. корректность `device_id` и `token`;
3. наличие установленных `mpv`, `wget`, `pdftoppm`;
4. существование и права на `media_dir`;
5. наличие графической сессии и переменных окружения `DISPLAY`/`XAUTHORITY`;
6. журналы `systemd` и stdout приложения.
